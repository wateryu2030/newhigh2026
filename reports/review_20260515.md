## 三、代码质量问题 (MEDIUM)

### 3.1 `gateway/endpoints.py` — 4,050 行超长文件
- 最大单一路由文件，含 `/market/*`, `/news/*`, `/skill/*`, `/system/*`, `/ai/*` 等 40+ 端点
- 函数内大量 `try/except/pass`，API 出错静默返回空数组，前端收到「假成功」(HTTP 200 with [])
- **建议**: 按领域拆分为 `endpoints_market.py`, `endpoints_news.py`, `endpoints_system.py`

### 3.2 except pass 模式泛滥
```python
try:
    ...
except Exception:
    pass  # 海量降级
```
- 全项目出现 50+ 处，包括 gateway, data-pipeline collectors, ai-models, strategy-engine
- 导致：DB 连接失败 → 静默返回空 → 前端展示空白页面（无错误提示）
- **建议**: 至少 `import traceback; traceback.print_exc()` 或 `log.error()`

### 3.3 类型提示 "暗伤"
- 全项目使用 `Dict[str, Any]`, `List[Any]`, `Optional[str]` 泛型，无具体类型定义
- mypy.ini 中 `disallow_untyped_defs = False`，等同关闭类型检查
- **建议**: 对 data-pipeline 返回值定义为 TypedDict

### 3.4 import 位置混乱
- `data_pipeline.storage.duckdb_manager` 在 gateway 端点函数内延迟导入
- 情绪模型 `emotion_cycle_model.py` 导入 `lib.database`（可能是旧项目遗留）
- **建议**: 统一到 `core.src.core.data_service`，消除跨模块 import 耦合

### 3.5 DB 连接管理
- 每个 API 端点独立 get_conn() → execute() → close()
- 无连接池，高频请求（如 30 秒刷新 Dashboard）反复开闭连接
- `read_only=False` 多处使用（包括只读端点），可能造成写锁竞争
- 注意: 最近有 commit 修复 `read_only=True`（e86acdd），方向正确
